# SeaShell 0.5 design

Date: 2026-09-07. Branch `0.5`, worktree `~/Desktop/seashell-0.5`. Base: main at c8cc877 (0.4.4).

This release removes Lookout, fixes the three bugs a month of daily use surfaced (find does not
jump, scrolling has no acceleration, double-clicking a path does nothing), makes the pane glow
honest, and adds three things that were deferred in the 7/31 spec: a session restore prompt, an
in-app updater and live file watching. Every decision below was put to Josh on 9/07 and approved.

## 0. Decisions, as answered

| Topic | Answer |
|---|---|
| Lookout | Strip entirely. Keep the pane glow and ping, but only when something actually needs him. |
| Find failure mode | Matches highlight, the view does not scroll to them. |
| Find features | Search as you type, match counter, highlight all with wrap-around, case and regex toggles. |
| Accelerated scrolling | Velocity ramp only. No modifier key, no keyboard jumps, no scrollbar. |
| Scrollback | 20,000 lines, fixed, no setting. |
| Path double-click failure | Nothing at all happens, for every path kind (tool lines, prose, truncated, wrapped). |
| Double-click action | Plain reveals in the tree. Cmd+double-click also opens a preview pane. |

| Directional pane focus | No. |
| Auto-update | Yes, prompt on launch, nothing installs without a click. |
| Live file watching | Yes. |

## 2. Find

### Where it stands

`FindBar.tsx` searches on Enter only. `PaneTerminal.findNext/findPrevious` call the search addon
with decorations. The addon's `_selectResult` selects the match and, only when the match row is
outside the viewport, calls `terminal.scrollLines(row - viewportY - rows/2)`. Josh sees the
highlight and no scroll, so that scroll is not reaching the viewport.

### The jump

1. Reproduce on a dev build driven over CDP (`--remote-debugging-port`, never the live app): open
   the bar in a pane with 2,000+ lines, search a word near the top, read `buffer.active.viewportY`
   before and after. Record the root cause in the commit that fixes it.
2. Whatever the cause, `PaneTerminal.find()` takes over the scroll: after a successful search it
   reads `term.getSelectionPosition()`, and if the start row is outside
   `[viewportY, viewportY + rows)` it calls `term.scrollToLine(row - floor(rows / 2))`, clamped to
   the buffer. The addon is asked for `noScroll: true` so the two never fight. This is a small,
   deterministic fix that survives any addon behaviour; the root cause is recorded, not relied on.

### The bar

`FindBar` gains: a 120 ms debounced search on every keystroke (`incremental: true`, so the addon
extends the current match instead of jumping when the query grows); a `resultIndex + 1 of
resultCount` counter, fed by the addon's `onDidChangeResults` through a new
`PaneTerminal.onSearchResults(cb)`; toggles for case (Aa) and regex (.*) held in the bar's state
and passed in every search; wrap-around, which the addon already does when `findNext` reaches the
end (verified in its source; a test asserts it stays that way). Enter steps forward, Shift+Enter
back, Escape closes and clears decorations, all as today. The 1,000-result decoration cap in the
addon stands; past it the counter reads `1000+`.

`onSearch` becomes `(query, direction, opts: { incremental, caseSensitive, regex }) => boolean`.
The file preview implements the same contract with a `RegExp` built from the query (escaped when
regex is off, `i` when case is off).

### Budget

Search-as-you-type on a 20,000-line buffer is measured on this Mac before it ships: a search must
stay under 50 ms on a full buffer. If it does not, the debounce grows to 200 ms; the feature does
not get pulled.

## 3. Scrolling

### Velocity ramp

New pure module `src/renderer/term/wheel-ramp.ts`:

```
class WheelRamp {
  constructor(opts?: { floor?: number; ceiling?: number; onset?: number; gain?: number; decayMs?: number })
  feed(deltaY: number, now: number): number   // returns the multiplier to apply
}
```

It keeps an exponential moving average of `|deltaY| / dt` over recent wheel events. Below `onset`
(a slow, deliberate trackpad scroll) the multiplier is exactly 1, so precision scrolling is
untouched. Above it the multiplier rises linearly with `gain` and is clamped at `ceiling` (8).
With no wheel event for `decayMs` (200) it resets to 1. The four constants are tuned live on
Josh's trackpad and mouse and recorded in the module.

`PaneTerminal` attaches a capture-phase `wheel` listener on its container that only measures. It
never calls `preventDefault`; xterm keeps handling the event. When the multiplier changes by 0.25
or more it sets `term.options.scrollSensitivity`, which xterm propagates to its scrollable element
on the option-change event (verified in xterm 6.0.0's Viewport). Two guards force 1x: the
alternate buffer (`term.buffer.active.type === 'alternate'`, where wheel events become arrow keys
for programs like less and vim) and any pane whose program has mouse tracking on
(`term.modes.mouseTrackingMode !== 'none'`; xterm hands those wheel events to the program). The multiplier is set back to 1 on blur and on dispose.

### Scrollback

`scrollback: 20_000`. xterm allocates every buffer line at full column width, so a pane that has
scrolled the whole buffer at 200 columns holds about 48 MB of cell storage, four times today.
Josh chose 20,000 over 50,000 with that in mind. No setting.

## 4. Path double-click

### Where it stands

The chain is: `mousedown` with `detail === 2` in `terminal.ts` (capture phase, because xterm's
`preventDefault` can suppress `dblclick`) -> `pathAtPoint` -> `tokenizeLine` ->
`fs:statBatch` against the pane's OSC 7 cwd -> `revealPath` root check (root is `$HOME`, set at
startup) -> `explorer.reveal` action (forces the sidebar open) -> `Explorer`'s reveal effect expands
the chain, selects, scrolls. The tokenizer was run against every Claude Code line shape Josh named
(tool lines, prose, backticks, `:line` suffixes, absolute, home, relative) and produced the right
candidate for all of them except two: `(src/x.tsx).` keeps its parentheses when a period follows
the closing bracket, and `…/renderer/x.tsx` comes through as a relative path that can never stat.

### Diagnosis first

Josh sees nothing at all. Before any fix, a dev build over CDP dispatches a real double-click on
a rendered path and logs each stage: the candidate, the cwd the stat used, the stat result, the
root check, the reducer, and whether the Explorer effect ran. The stage that dies is fixed and
its cause recorded in the commit. Ranked suspicions: the capture-phase `mousedown` handler no
longer seeing `detail === 2` under xterm 6; a cwd of `''` before the first prompt, which makes
every relative candidate resolve nowhere; the Explorer effect not running because the component
mounts on the same render that carries the reveal.

### Fixes regardless of the diagnosis

1. **Wrapped rows.** Claude Code hard-wraps its own output, so xterm never marks the second row
   as wrapped and the logical line is one row. New pure module `src/renderer/links/wrap-join.ts`:
   given the clicked row's candidate and the raw text of the rows above and below, it returns an
   ordered list of candidates to try: the token alone; the token joined with the leading
   non-space run of the next row when the token reaches the last two columns; the trailing
   non-space run of the previous row joined with the token when the token starts at column 0;
   both. One `statBatch` call carries the whole list and the first hit in order wins.
2. **Truncated paths.** A candidate beginning with `…/` or `.../` is a suffix. New main handler
   `fs:findBySuffix { root, suffix, limit }` walks the explorer root with the existing tree and
   gitignore modules, depth-capped at 12 and entry-capped at 50,000, and returns every path ending
   in the suffix. One hit reveals. Several show a toast naming the count and the first three.
   None shows the miss toast.
3. **Bracket bug.** Trailing punctuation is stripped before balanced brackets, so
   `(src/x.tsx).` yields `src/x.tsx`. Test added.
4. **A miss is never silent.** When every candidate resolves nowhere the pane toasts
   `No file at <candidate> from <cwd>`. The existing outside-the-explorer toast stays.
5. **Modifiers.** `onDoubleClick(x, y, mods: { meta, alt })`. Plain reveals. Cmd reveals and
   opens the resolved file through the existing `fs:probe` route the explorer uses (preview pane
   leaf, or the OS for what the viewer refuses). Cmd+Opt reveals and opens it in the OS default
   app through the existing open IPC; executables are refused and revealed in Finder with the
   explorer's toast. Directories never open anywhere; they expand in the tree.

## 5. Glow and ping accuracy

### Why it lies today

`classifyActivity` marks a pane `WAITING` when a non-shell program has low CPU and low output, and
`nextAttention` turns 20 seconds of that into `waiting`. That is the resting state of every idle
Claude, so a pane that finished an hour ago and needs nothing glows exactly like one asking a
question.

### Event-driven waiting

`waiting` becomes an event, not an inference. The source is the terminal bell:

- `PaneTerminal` subscribes `term.onBell` and forwards it as `onBell()`. `PaneView` dispatches
  `pane.bell { paneId, at }`. The pane record gains `bellAt?: number`.
- `nextAttention` drops `waitingSince` and `WAITING_SETTLE_MS`. Its input gains
  `bellSinceLastTick: boolean`. The rule: `waiting` when a bell arrived, the pane is not focused,
  and its foreground is not the bare shell (`next !== 'PROMPT'`, so a completion beep at a prompt
  does not glow). `waiting` clears on focus, as today. The ping fires on the transition, as today.
- The `done` pulse is unchanged: it keys off `BUSY` or `WAITING` turning into `PROMPT`, which is
  the process tree returning to the shell and is accurate.
- `classifyActivity` and the `PaneActivity` type are untouched. `WAITING` is still computed and
  still shown wherever it is shown; it just no longer drives the glow.

Claude Code rings the bell when `preferredNotifChannel` is `terminal_bell`: on a permission prompt
that has waited about six seconds, and about sixty seconds after a turn ends with nothing typed.
Josh's `~/.claude/settings.json` gets that one key, approved 9/07. Which events ring is verified
live on a dev build before ship and written into the README, which tells other users to set the
same key. Programs that wait for input without ringing no longer glow; that trade was chosen.

Tests: `attention.test.ts` is rewritten around the bell input, including the prompt-beep guard
and the focus reset. The bell wiring is covered by the CDP smoke (write `\x07` to a pane's pty
with a sleeping foreground program and watch the glow).

## 6. Session restore prompt

### Snapshot

Main `src/main/state/last-session.ts`: `saveLastSession(tabs: SavedTab[])` writes
`<userData>/last-session.json` as `{ schemaVersion: 1, savedAt, tabs }`; `loadLastSession()`
returns the tabs or `null` on a missing, corrupt or mismatched file; `clearLastSession()` removes
it. IPC `session:save`, `session:load`, `session:clear`. Same `SavedTab` shape as projects, same
`sessionIdsForPanes` lookup for Claude session ids, so nothing new is serialized.

The renderer snapshots every 30 seconds and skips the write when nothing has changed since the
last one. It also snapshots at quit: the existing `will-quit` drain first asks the renderer for a
final snapshot with a one-second timeout, then runs the kill ladder. A window holding a single
fresh pane with no Claude session is not worth a prompt, so it saves nothing and clears any older
file.

### Launch

Before spawning the default pane, `app.tsx` loads the last session. If there is one, the empty
window shows a `RestoreCard`: the tab and pane count, when it was saved, and two buttons.
**Restore** runs the existing `restoreProjectTabs` with the snapshot, so every Claude pane resumes
through `claude -r <id>` in the permission mode it last ran in. **Start fresh** clears the file
and spawns the default pane. Nothing spawns until one is clicked, and Escape means Start fresh.

Tests: unit round trip, corrupt file, schema mismatch, the skip rule; a dom test for the card.

## 7. Auto-update

### Why not electron-updater

Its macOS path runs through Squirrel.Mac, which validates the code signature of the downloaded
bundle against the running one and refuses ad-hoc signatures. SeaShell is ad-hoc signed by
necessity and by choice (see the 7/31 spec and the 0.2.8 note). The in-house path below is the
manual swap Josh already does, automated, and it works with the signature the app has. If a
Developer ID ever arrives, electron-updater becomes the upgrade.

### Check

Main `src/main/update/check.ts` is pure: `parseRelease(json) -> { version, zipUrl, dmgUrl, pageUrl }
| null` picks the `SeaShell-<version>-universal.zip` asset and only accepts URLs under
`https://github.com/voidharbor/seashell/releases/download/`; `isNewer(candidate, current)` is a
strict semver compare. `src/main/update/updater.ts` runs once per launch, five seconds after the
window shows, with a five-second timeout, against
`https://api.github.com/repos/voidharbor/seashell/releases/latest`. It does nothing when the app
is unpackaged, when `SEASHELL_NO_UPDATE_CHECK` is set, or when the running bundle is not the
installed one under `/Applications` (then the banner offers the release page only). A version
dismissed with Later is remembered in settings and not offered again.

### Download and install

The zip downloads to `<userData>/updates/SeaShell-<version>-universal.zip` with progress events,
and its size must match the asset's declared size. Install writes a small shell script to
`<userData>/updates/install.sh` and spawns it detached with `nohup`; then the app quits normally,
so the kill ladder runs and the singleton lock releases. The script: waits for the app's pid to
exit (up to 30 seconds), extracts the zip with `ditto -x -k` into a staging directory, checks that
the staged bundle's `Info.plist` carries the expected version, replaces the installed bundle with
the staged one, clears quarantine on it, and relaunches it with `open -a`. Any failed step leaves
the current install untouched and writes `install.log` beside the script, which the next launch
surfaces as a toast. The script text is built by a pure function and tested for its exact commands.

### Banner

`UpdateBanner` sits above the status bar: `SeaShell 0.6.0 is available` with Download and Later;
then a progress bar; then Install and Relaunch, labelled plainly that it closes every pane. IPC:
`update:state` (event), `update:download`, `update:install`, `update:dismiss`. Linux and Windows
get the banner with the release page link only; the installer is macOS in 0.5.

### Packaging

`dist:mac` builds `dmg` and `zip`, both universal. `release.yml` is unchanged; the mac assets stay
a local build. The README install section mentions the updater and the one-time quarantine
command for first installs.

## 8. Live file watching

Per the 7/31 spec, section 19.4, built as designed there:

- Main `src/main/fs/watcher.ts` wraps `fs.watch(dir, { persistent: false })`, one non-recursive
  watch per directory. Pool logic lives in pure `watcher-pool.ts`: at most 64 handles, evicting the
  least recently rendered (the renderer sends `watch:touch` when it paints a directory), a 250 ms
  debounce per path, and a refusal for any directory the gitignore module marks ignored.
- IPC: `watch:subscribe { dir }`, `watch:unsubscribe { dir }`, `watch:touch { dir }`, and the event
  `watch:changed { dir }`. `EMFILE`, `ENOENT` and any watcher error drop that watch quietly and
  emit `watch:lost { dir }` so the explorer can fall back to its click-to-refresh behaviour.
- Explorer: subscribe on expand, unsubscribe on collapse and on root change, and on `changed` for
  an expanded directory call the existing `load(dir)`, preserving selection and expansion. The
  reveal path is untouched; it already re-reads its chain.

Tests: the pool (LRU, debounce, ignore refusal) in unit; one node-env integration test that
creates a file in a temp directory and expects `changed` within a second.
